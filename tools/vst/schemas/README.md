# VST control-plane contracts (human-readable schema)

Implemented in `tools/vst/contracts.py`, `tools/vst/signing.py`, `tools/vst/gate.py`. Standard library only. All validators require the EXACT key set (missing and unknown fields are rejected), have no defaults, never accept `bool` as `int`, and return a deep copy. Violations raise `ContractError` (a `ValueError`) naming the field.

Closed enums: `RESULT` = PASS, FAIL, BLOCKED, NOT_RUN, INCONCLUSIVE. `COVERAGE` = FULL, PARTIAL, NOT_COVERED. `VERDICT` = APPROVE, APPROVED_WITH_WAIVER, MODIFY, NO_GO. `RECEIPT_TYPES` = TestRun, StaticAnalysis, IndependentReview, Documentation. Hashes are lowercase hex (head = 40 chars, sha256 = 64). Dates are opaque non-empty strings.

## TaskManifest (`validate_task_manifest`)

| Field | Type / rule |
|---|---|
| task_id, project_id, story_id, owner_role, model_policy | non-empty str |
| phase | int 1..10 |
| base_head | 40 hex |
| scope | non-empty list of unique repo-relative paths: no absolute path, no leading `/` or `\`, no `:`, no empty / `.` / `..` segments |
| forbidden_actions, tools | list of unique non-empty str (may be empty) |
| role_sha256 | 64 hex |
| skills | list of `{id: non-empty str, sha256: 64 hex}`, unique ids (may be empty) |
| acceptance | non-empty list of unique non-empty str ids |
| required_receipts | non-empty list of `{slot: unique non-empty str, receipt_type: RECEIPT_TYPES}`; must contain at least one TestRun and one IndependentReview slot; the slot name `__supervisor__` (`SUPERVISOR_SLOT`) is reserved and rejected |
| author_principal | non-empty str (non-empty after `normalize_principal`: Unicode NFKC, then strip + casefold; after NFKC a string containing a control (Cc), format / zero-width (Cf), surrogate (Cs), private-use (Co) or unassigned (Cn) character, a variation selector (U+FE00-FE0F, U+E0100-E01EF), or one of the filler characters U+034F, U+115F, U+1160, U+17B4, U+17B5, U+2800, U+3164, U+FFA0 is rejected; the closed list is not a full homoglyph defence) |
| required_tests | list of `{slot, test_id, acceptance}` (REQUIRED, no default): `slot` is a TestRun slot, `test_id` non-empty str unique per slot, `acceptance` non-empty list of str, every id present in manifest `acceptance`; every TestRun slot needs at least one |
| allowed_commands | list of `{slot, argv}` (REQUIRED): `slot` is a TestRun slot, `argv` non-empty list of str; every TestRun slot needs at least one |
| required_rules | list of `{slot, rule_id}` (REQUIRED): `slot` is a StaticAnalysis slot, unique per slot; every StaticAnalysis slot needs at least one |
| timeout_sec | int > 0 |
| cost_cap, retry_cap | int >= 0 |

`manifest_sha256(manifest)` = sha256 hex of `canonical_bytes` of the validated manifest. Receipts and waivers bind to it.

### Explicit v2 manifest additions

V1 manifests keep their original exact field set and canonical bytes. V2 is selected only by
`contract_version: 2`; its exact field set is the v1 fields plus `contract_version`,
`reviewer_registry: {version, sha256}`, `mandatory_commands`, and
`change_scope: {allowed_paths}`. `mandatory_commands` is a non-empty list of exact
`{slot, argv, parser_id, parser_version, parser_sha256}` objects, with at least one entry
for every TestRun slot. Parser selection is by the exact triple in the built-in
`TRUSTED_PARSER_CATALOG`; the caller cannot add implementations. `change_scope.allowed_paths`
is a unique non-empty repo-relative path list.

V2 TestRun receipts add exact `contract_version: 2`, `parser_results`, signed `diff_gate`
evidence, and `runner_attestation`. Parser results bind each argv and parser triple to exact
executed/skipped/xfail test id lists. Diff evidence binds `manifest_sha256` and
`candidate_head`, includes its digest/path/verdict/reason, and has a distinct domain-separated
signature. Runner attestation contains the exact signer request and its signature; the gate
checks its fields against the receipt and manifest. V2 IndependentReview receipts add
`reviewer_key_id` and are verified with the mapped reviewer key under a separate signature
domain. The operator-signed reviewer registry contains `{version, entries, signature}`;
each entry is `{principal, key_id}` and the manifest binds its version and canonical content
digest. V1 evidence cannot satisfy a v2 manifest.

V2 waivers add `waived_results`; its non-empty list may contain only `NOT_RUN`,
`INCONCLUSIVE`, or `BLOCKED`. Missing evidence, `FAIL`, reviewer `MODIFY`, and `NO_GO` are
not waivable. The gate rejects a waiver unless each unmet result is explicitly in that list.

## Receipt (`validate_receipt`)

Common fields: `manifest_sha256` (64 hex, REQUIRED, must equal `manifest_sha256(manifest)` at the gate); a receipt whose `slot` is `SUPERVISOR_SLOT` must be a Documentation receipt; `receipt_id`, `task_id`, `slot` (matches a manifest slot or `SUPERVISOR_SLOT`), `runner_id`, `resolved_model`, `invocation_id`, `created_at` are non-empty str; `receipt_type` in RECEIPT_TYPES; `attempt` int >= 1; `prev_receipt_sha256` is null iff attempt == 1, else 64 hex; `candidate_head` 40 hex; `epoch` int >= 1; `role_sha256` 64 hex; `result` in RESULT; `signature` 64 hex.

Per type (lists contain non-empty str unless stated):

- TestRun: `expected_test_ids`, `executed_test_ids`, `skipped_test_ids`, `xfail_test_ids`, `covered_acceptance`; `commands` = non-empty list of `{argv: non-empty list of str, exit_code: int}`; `artifact_digests` (REQUIRED, may be empty) = dict mapping a repo-relative path str (same rules as manifest `scope`: no absolute path, no `:`, no empty / `.` / `..` segments, no surrounding whitespace) to a 64-hex sha256 of that artifact as it was after the commands ran. The all-zero digest (`MISSING_ARTIFACT_DIGEST`, 64 zeros) means "artifact missing after the run".
- StaticAnalysis: `coverage` in COVERAGE; `covered_rules`, `unsupported_rules`, `covered_acceptance`.
- IndependentReview: `reviewer_principal`, `author_principal` (non-empty str); `covered_acceptance`, `findings`; `signed_verdict` in {MODIFY, NO_GO, APPROVE}.
- Documentation: `check_description` non-empty str; `covered_acceptance`.

## derive_result (what `result` MUST be)

- TestRun: FAIL if `artifact_digests` contains the all-zero digest (checked first); otherwise INCONCLUSIVE if `executed_test_ids` is empty; PASS only if every `exit_code == 0`, `expected_test_ids` non-empty, set(executed) == set(expected), and `skipped_test_ids` and `xfail_test_ids` are empty; otherwise FAIL.
- StaticAnalysis: PASS only if `coverage == FULL`, `unsupported_rules` is empty and `covered_rules` is non-empty; otherwise INCONCLUSIVE.
- IndependentReview: PASS only if `signed_verdict == APPROVE` and `normalize_principal(reviewer_principal) != normalize_principal(author_principal)` (both non-empty after normalization); otherwise FAIL.
- Documentation: the given `result` if it is PASS or FAIL; otherwise INCONCLUSIVE.
- Rule for every receipt type, applied first: a given `result` of BLOCKED, INCONCLUSIVE or NOT_RUN is accepted as given (`NON_APPROVING_RESULTS`). These results can never produce an approval (the gate treats any non-PASS latest attempt as an unmet slot), and the supervisor must be able to write INCONCLUSIVE(WORKER_LOST), BLOCKED(RETRY_EXHAUSTED) and BLOCKED(budget) receipts. A given PASS or FAIL is still compared with the computed value.
- Reason codes: receipts have closed fields, so there is no `reason` field. Supervisor receipts are of type Documentation and carry the reason code in `check_description` (`WORKER_LOST`, `RETRY_EXHAUSTED`, `BUDGET_EXCEEDED`).

The gate treats a receipt whose `result != derive_result(receipt)` as invalid.

## Canonical form and signature

`canonical_bytes(obj)` = `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False)` encoded as UTF-8. `receipt_sha256(receipt)` = sha256 hex of the canonical bytes of the FULL receipt including `signature`. `signing.sign(obj_without_signature, key, label=RECEIPT_LABEL)` = HMAC-SHA256 hex over `label + canonical_bytes(obj)`; `signing.verify(obj, key, label=RECEIPT_LABEL)` recomputes over the object minus `signature` and compares with `hmac.compare_digest`; it returns False (does not raise) for a malformed object or signature. Labels are domain separators: `RECEIPT_LABEL = b"vst-receipt-v1\0"` (receipts, worker key or supervisor key) and `WAIVER_LABEL = b"vst-waiver-v1\0"` (operator waivers). A key must be bytes of length >= 32, else `ContractError`.

Waiver (gate input, signed by the operator key with `WAIVER_LABEL`): exact keys `record_id`, `operator`, `task_id`, `head`, `manifest_sha256` (non-empty str), `epoch`, `expires_epoch` (int), `waived_slots`, `waived_acceptance` (list of str), `signature` (64 hex).

## GateDecision (`validate_gate_decision`)

`task_id` str, `candidate_head` str (echoes of gate inputs, so that NO_GO can be emitted for malformed inputs), `epoch` int >= 0, `required_receipt_hashes` list of 64 hex, `unresolved_findings` / `human_approvals` / `acceptance_unmet` / `reasons` lists of non-empty str, `verdict` in VERDICT, `waiver_record` non-empty str iff verdict is APPROVED_WITH_WAIVER, else null. APPROVE additionally requires empty `reasons` and `acceptance_unmet`.

## Store (`tools/vst/store.py`)

`Store(path, clock=time.time, *, event_key, busy_timeout_sec=30.0)`: one sqlite3 connection per instance, WAL, `foreign_keys` and `recursive_triggers` ON, autocommit with an explicit `BEGIN IMMEDIATE` per mutating method; `_tx` always ends with an explicit COMMIT or ROLLBACK (each public method is atomic). SQLite busy/locked errors become `StoreBusyError` (a `StoreError`, kind `busy`). Context manager closes the connection. `StoreError(message, kind)`; kinds: story, epoch, lease, slot, chain, duplicate, budget, argument, append_only, task, manifest, signature, supervisor, retry, terminal, key, integrity, schema, busy. All keys (`event_key`, worker `key`, `supervisor_key`) are bytes of length >= 32. Every supervisor operation (`acquire_lease`, `charge`, `append_supervisor_receipt`, `supervisor_reap_and_mark`, `mark_budget_exceeded`) refuses a `supervisor_key` equal to the `event_key` (`kind='key'`).

Schema: `PRAGMA user_version` = 3 (`SCHEMA_VERSION`; v3 adds `leases.receipt_count` and the `LEASE_EXPIRED_PARTIAL` event kind); a new file is initialised in one transaction, a legacy un-versioned database with tables or any other version is refused (`kind='schema'`). The database file and its `-wal`/`-shm` get `chmod 0o600` (best effort). Integer arguments are bounds-checked (epoch/attempt <= 2^31-1, budget values <= 10^12, slots <= 1024, ttl <= one year, finite).

Tables: `stories(story_id, project_id, phase 1..10, epoch, owner, state in OPEN/OWNED, owner_expires_at)`, `tasks(task_id, story_id, manifest_sha256, retry_cap, manifest)` (append-only; the task/story link is stored once), `leases(lease_id, task_id, story_id, attempt, worker_id, epoch, expires_at, status in LIVE/RELEASED/EXPIRED/FENCED, wrote, marked, receipt_count, UNIQUE(task_id, attempt))` (history; at most one LIVE lease per task via a partial unique index), `slots(slot_no, lease_id, expires_at)` (concurrency slots), `receipts(seq, receipt_id UNIQUE, story_id, task_id, slot, attempt, epoch, receipt_sha256, prev_receipt_sha256, body, UNIQUE(task_id, slot, attempt))`, `events(seq, ts, task_id, actor, kind in EVENT_KINDS, payload, prev_hash, hash)`, `budget(task_id, cap, spent)`, `meta(key, value)` (keyed event anchor).

- Append-only: triggers `RAISE(ABORT)` on UPDATE and DELETE of `receipts`, `events` and `tasks`, on DELETE of `leases`, on changing a lease identity column, and on reopening a closed lease. A `sqlite3.IntegrityError` from these triggers inside a Store transaction is re-raised as `StoreError(kind='append_only')`; no Store method mutates receipts or events.
- Task registration: `register_task(manifest) -> manifest_sha256` stores the validated manifest once (story must exist and share `project_id`); the identical manifest again is a no-op, a different manifest for the same `task_id` is `StoreError(kind='manifest')`. `get_manifest(task_id)` returns the stored manifest. Leases, receipts and markers require a registered task.
- Epoch: `open_story` starts at epoch 1 with no owner. `acquire_epoch(story_id, owner, ttl_sec=3600)` is a compare-and-swap: it bumps the epoch and returns it only when no live owner holds the story, otherwise `StoreError(kind='epoch')`. Winning fences the story's live leases (status FENCED, slots freed). `renew_epoch(story_id, owner, ttl_sec)` and `release_epoch(story_id, owner)` are owner-only (`kind='epoch'` otherwise).
- Phase: `set_phase(story_id, owner, epoch, phase)` is a compare-and-swap on the epoch by the live owner (`kind='epoch'` on any mismatch) and records `PHASE_SET`; `get_phase(story_id)` reads it; `render_state_md` prints it.
- Leases: `acquire_lease(task_id, story_id, worker_id, epoch, attempt, ttl_sec, *, supervisor_key)` INSERTs a history row and takes a free slot in the same transaction; it fails for a stale epoch, an unknown task or wrong story, a live lease, a previous lease lost and not yet marked, an attempt other than previous + 1 (`kind='lease'`), no free slot (`kind='slot'`), or a terminal marker / retry cap (below). `wrote` becomes 1 and `receipt_count` grows when the holder appends a receipt. A lease that wrote at least one receipt and then expired (EXPIRED by reaping) records a `LEASE_EXPIRED_PARTIAL` event with the receipt count, in addition to `LEASE_EXPIRED`, and gets no `WORKER_LOST` marker. `heartbeat` and `release_lease(task_id, worker_id, epoch)` reject expired, foreign or stale-epoch callers.
- Retry cap: `retry_cap` bounds only WORKER-ATTRIBUTED failed attempts. `failed_attempts(task_id)` = (the largest number of non-PASS worker results, i.e. `FAIL`, `INCONCLUSIVE`, `NOT_RUN`, `BLOCKED`, in any single worker slot) + (the number of EXPIRED or RELEASED leases that wrote no receipt). FENCED leases (epoch takeover) are never counted, so a takeover cannot exhaust the cap. `acquire_lease` refuses when `failed_attempts >= retry_cap + 1`: the first refusal commits a signed `RETRY_EXHAUSTED` supervisor marker (BLOCKED) and then raises `StoreError(kind='retry')`; later attempts raise the same error without a second marker. Lease attempts stay consecutive per task (previous + 1) and receipt attempts consecutive per `(task_id, slot)` chain; `append_receipt` refuses (`kind='retry'`) a receipt when the slot already has `retry_cap + 1` attempts in the CURRENT epoch; attempt numbers stay globally consecutive across epochs, so a takeover after a full PASS set remains satisfiable. `acquire_epoch` reaps expired leases first (they become EXPIRED and markable, not FENCED); `heartbeat` refuses after a terminal marker (`kind='budget'` or `'terminal'`) or an exceeded budget.
- Worker receipts: `append_receipt(receipt, story_id, key)` verifies in order: contract validity; slot is not `SUPERVISOR_SLOT` (`kind='supervisor'`); registered task and story (`task`/`story`); `manifest_sha256` and `role_sha256` equal the registered manifest (`manifest`); slot declared with the receipt type (`slot`); HMAC with the worker key and `result == derive_result` (`signature`); `epoch` == current story epoch (`epoch`); no terminal marker (`terminal`); budget not exceeded, i.e. `spent <= cap` (spending exactly the cap still allows the final receipts) and no `BUDGET_EXCEEDED` event (`budget`); worker key differs from the `event_key` (`key`); a LIVE, unexpired lease whose `worker_id == runner_id` at the same epoch (`lease`); the slot holds fewer than `retry_cap + 1` receipts in the CURRENT epoch (`retry`; attempt numbers are global and have no upper bound of their own); attempt == last + 1 per `(task_id, slot)` and `prev_receipt_sha256` == previous hash (`chain`); unique `receipt_id` (`duplicate`).
- Supervisor isolation: receipts in `SUPERVISOR_SLOT` are written only by `append_supervisor_receipt(receipt, story_id, *, supervisor_key)` and the supervisor methods, verified with the supervisor key only (no lease; the key is the authority); `check_description` must be `WORKER_LOST` (INCONCLUSIVE), `BUDGET_EXCEEDED` or `RETRY_EXHAUSTED` (BLOCKED), with empty `covered_acceptance`; terminal markers are unique per task. A worker lease and worker key cannot write the supervisor slot, and the supervisor path cannot write worker slots.
- Supervisor methods: `supervisor_reap_and_mark(supervisor_key, runner_id)` reaps expired leases and, for every EXPIRED or FENCED unmarked lease whose holder never wrote a receipt (`wrote = 0`), appends a signed Documentation `WORKER_LOST` marker (INCONCLUSIVE) to `SUPERVISOR_SLOT`, then sets `marked`. `mark_budget_exceeded(task_id, supervisor_key, runner_id) -> dict` appends the BLOCKED `BUDGET_EXCEEDED` marker and a `BUDGET_BLOCKED` event (the same helper `charge` uses); it is idempotent (a second call returns the existing marker). Marker attempt = next in the supervisor chain; epoch = current story epoch; `candidate_head` = head of the task's latest receipt, else manifest `base_head`; `manifest_sha256` from the registered task.
- Events: closed enum `EVENT_KINDS` (also a CHECK constraint); callers may record only `NOTE` via `record_event` (`OPERATOR_ACTION` is no longer a caller kind). `hash = HMAC-SHA256(event_key, label + prev_hash + canonical JSON of {ts, task_id, actor, kind, payload})`, first `prev_hash` is 64 zeros. A keyed anchor row in `meta` (count, head hash, HMAC) is updated with every event. BEFORE every event append the store verifies the anchor MAC, `count == COUNT(*)` of events and `head ==` hash of the last event; any mismatch (or a missing anchor while events exist) raises `StoreError(kind='integrity')` and nothing is recomputed or repaired (there is no silent fallback). `verify_event_chain` recomputes the chain and checks the anchor, so editing, inserting, deleting or truncating events is detected (only a rollback to an older consistent database copy is not); `event_anchor() -> (count, head)` returns the verified pair for anchoring outside the database (`kind='integrity'` if it does not verify). `verify_event_chain`, `event_anchor`, `failed_attempts` and `render_state_md` read inside one explicit read transaction (`BEGIN` ... end), so concurrent writers cannot cause a false tamper result.
- Budget: `register_task` seeds the budget row (`cap = manifest cost_cap`, `spent = 0`); `set_budget(task_id, cap)` needs a registered task, refuses a cap above the manifest `cost_cap` (`kind='budget'`) and a cap below `spent` (`kind='argument'`). `append_receipt` refuses (`kind='budget'`, or `'terminal'` after the marker) only when `spent > cap` or a `BUDGET_EXCEEDED` event or marker exists; `acquire_lease` refuses at `spent >= cap` and first commits the signed `BUDGET_EXCEEDED` marker (event recorded once), then raises `kind='budget'`. `charge(task_id, amount, *, supervisor_key, runner_id='store-supervisor')` never lets `spent` exceed `cap`; on overflow it commits the `BUDGET_EXCEEDED` event and the signed `BUDGET_EXCEEDED` supervisor marker (plus `BUDGET_BLOCKED`, once) and then raises `StoreError(kind='budget')` without charging. `mark_budget_exceeded` stays idempotent.
- `receipts_for_task(task_id)` verifies the event anchor and checks, in one read transaction, that the set of `RECEIPT_APPENDED` event sha256 values of the task equals the set of receipt row digests; a mismatch raises `StoreError(kind='integrity')`.
- Key rules: what the store enforces vs the gate. The store enforces only that the worker key differs from the `event_key` (`append_receipt`) and that the supervisor key differs from the `event_key` (all supervisor operations). `append_receipt` has no supervisor key, so pairwise distinctness including worker vs supervisor vs operator is enforced by the gate (`NO_GO`) and by the slice fixture; key isolation between processes is owned by S2.
- `render_state_md(story_id)`: deterministic markdown view (phase, epoch, the full lease history with status/wrote/marked, receipts), first line states it is a generated view that must not be edited.

## Runner (`tools/vst/runner.py`)

`run_and_sign(*, manifest, slot, attempt, epoch, candidate_head, resolved_model, invocation_id, runner_id, key, commands, expected_test_ids, test_result_parser, covered_acceptance, artifact_paths, prev_receipt_sha256, cwd, created_at, timeout_sec=None, deadline_sec=None, max_output_bytes=1048576, extra_env=None, report=None)` takes the whole manifest; `task_id`, `role_sha256` and `manifest_sha256` of the receipt come from it. It validates EVERYTHING before any process starts and raises `ContractError`: valid manifest; `slot` is a TestRun slot (the per-epoch `retry_cap` bound is enforced by the store, not here); ids, hex lengths and `prev_receipt_sha256` (null iff attempt == 1); worker `key` bytes of length >= 32; every `argv` EXACTLY equals an `allowed_commands` entry of the slot; `sorted(expected_test_ids)` equals the manifest `required_tests` ids of the slot; `covered_acceptance` is a subset of manifest `acceptance`; `artifact_paths` are unique repo-style relative paths (no absolute path, no `..`, no drive letter) that stay under `cwd` and cross no symlink or junction; `timeout_sec` (per command) and `deadline_sec` (overall) are ints in [1, manifest `timeout_sec`] and default to the manifest value; `max_output_bytes` in [1, 64 MiB]; callable parser. A cwd that does not exist is not a validation error (exit code -2).

Execution: `subprocess.Popen(shell=False)`, stdin from the null device, started in its own process group (POSIX) / process group without a window (Windows). The child gets a minimal explicit environment: the allowlisted names `ENV_ALLOWLIST` (PATH, PATHEXT, SYSTEMROOT, SYSTEMDRIVE, WINDIR, TEMP, TMP, TMPDIR, LANG, LC_ALL) copied from the runner process, `PYTHONIOENCODING=utf-8` and the caller's explicit `extra_env`; nothing else is inherited. `extra_env` is an allowlist: every name must fully match `VST_[A-Z0-9_]+` (case-sensitive); anything else is rejected with `ContractError` (a `ValueError`) before anything runs. stdout and stderr are read by threads and capped at `max_output_bytes` each (excess drained and dropped). Process-tree containment: on Windows the child is assigned right after `Popen` to a Job Object created with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (stdlib `ctypes`, import-safe elsewhere); on EVERY exit path (normal exit, timeout/deadline, output cap, any exception) the runner calls `TerminateJobObject` then `CloseHandle`, so descendants die even after the root has exited. Known tiny race: the child is not started suspended, so a grandchild spawned before the assignment is not a member. If the assignment fails (for example the process already belongs to a non-nestable job) the runner falls back to `taskkill /PID <pid> /T /F` (failures ignored; best effort once the root has exited) and reports `job_object: False`; on timeout `taskkill /T /F` also runs as an extra fallback. On POSIX the process group is killed with `os.killpg(SIGKILL)` on timeout and after a normal exit. Recorded exit codes: the process exit code; -1 timeout or deadline reached (commands not started before the deadline are recorded as -1 without running); -2 missing executable / cwd / permission / any `OSError` at start (non-OSError exceptions propagate); -3 `EXIT_OUTPUT_TRUNCATED` when either stream exceeded the cap (fail-closed: the result derives to FAIL); -4 `EXIT_CAPTURE_INCOMPLETE` when a reader thread is still alive after the join, a pipe read failed with any exception, or the root process survived the kill for 10 s (takes precedence over -1 and -3; fail-closed, derives to FAIL). If `report` is a dict it receives `{"commands": [{stdout_truncated, stderr_truncated, timed_out, capture_incomplete, job_object, skipped_by_deadline}, ...], "capture_incomplete": bool}`; `job_object` is True only when the command ran inside a Windows Job Object (if the attachment fails on Windows the run continues with the taskkill fallback). On any exception the process tree is killed and the pipes are closed after the readers are joined.

Then stdout of all commands is joined and given to the injected parser (`(executed, skipped, xfail)`), the TestRun receipt (with `manifest_sha256`) is built, `result = derive_result(receipt)`, signed with `signing.sign` and validated. Artifacts are hashed AFTER the commands (relative to `cwd`; the path as given is the key in `artifact_digests`); a missing, non-regular, symlinked or escaping artifact gets the all-zero digest (FAIL). The key is a plain argument: never written, logged, passed to a child or read from the worker cwd. Helpers: `file_sha256(path)`, `artifact_digests(paths)`, `build_environment(extra_env)`, `contained_artifact_path(cwd, rel)`.

## Slice harness (`tools/vst/slice.py`)

Synthetic vertical slice: no real project, no network; exactly one scenario (`real_run_and_sign`) starts a tiny subprocess (the current Python printing two lines) through the real runner, everything else is deterministic. `build_synthetic_manifest(task_id, base_head)` returns a valid manifest with slots `tests` (TestRun, tests `t1`, `t2` for AC-1, allowed commands `["synthetic-test-run"]` and the real Python one-liner), `static` (StaticAnalysis, rules `R1`, `R2`), `review` (IndependentReview), `author_principal` `author-1`, acceptance `AC-1`, `AC-2`, `retry_cap` 1. `SliceFixture(workdir, key, clock, *, supervisor_key, operator_key, event_key)` requires four pairwise distinct keys of at least 32 bytes (defaults derived from fixed labels; `key` is the worker key), creates `workdir/state.db`, registers the task, acquires the epoch, and builds signed receipts directly (`make_test_receipt`, `make_static_receipt`, `make_review_receipt`, `make_supervisor_receipt`, operator-signed `make_waiver`). `begin(attempt)` / `end()` acquire and release the worker lease (the lease holder and every receipt `runner_id` are `runner-1`); `append` needs a live lease. `gate(receipts=None, waiver=None)` evaluates with receipts read from the store when not given. `run_scenarios(workdir)` runs nineteen named scenarios (the last two are `budget_exact_cap_allows_final_receipts` and `takeover_after_full_pass_set`, the latter on a `retry_cap` 0 manifest; `build_synthetic_manifest` and `SliceFixture` take an optional `retry_cap`, default 1) (happy_path, worker_death_before_receipt, zombie_late_write, stale_head, retry_after_fail, forged_receipt, partial_static_coverage, missing_required_receipt, not_run_with_waiver, budget_exceeded, real_run_and_sign, retry_exhausted, forged_supervisor_receipt, manifest_swap, retry_across_head_change, worker_lost_before_first_receipt, takeover_does_not_exhaust_retry_cap), each in its own subdirectory with a fake clock, and returns `{name: {verdict, reasons, unresolved_findings, extra}}`. Expected `StoreError`s are caught and reported in `extra`; anything else propagates. CLI: `python -m tools.vst.slice <directory>` prints a sorted-key JSON report.

## Gate rules

`gate.evaluate(manifest, receipts, current_head, current_epoch, key, *, supervisor_key, operator_key=None, waiver=None, artifact_resolver=None)` is pure and default-deny; the rule order and the verdict logic are specified in the `tools/vst/gate.py` module docstring. Summary:

- Keys: worker receipts verify with `key`, receipts in `SUPERVISOR_SLOT` with `supervisor_key`, the waiver with `operator_key` and `WAIVER_LABEL`; all keys are bytes of length >= 32. `key`, `supervisor_key` and `operator_key` (when given) must be pairwise distinct (bytes comparison); otherwise the verdict is `NO_GO` with a reason.
- Every receipt must be valid, for this task, carry the manifest's `manifest_sha256` and `role_sha256`, have `epoch <= current_epoch` (a larger epoch is the hard reason `future epoch`), be correctly signed and have a derived-consistent result. An older epoch is history, not an error.
- Head rule: the `candidate_head == current_head` check and the artifact-digest/resolver checks apply ONLY to the deciding receipt of each real slot (the latest attempt of an intact chain). Older attempts are history: they get no head or artifact reason; an older attempt at another head is listed in `unresolved_findings` as `history attempt at other head: <slot> attempt <n>`. A deciding receipt at a stale head is a hard reason (`stale head`) and leaves the slot unmet; if every deciding receipt is stale (head or future epoch) the verdict is `NO_GO`. `SUPERVISOR_SLOT` markers are exempt from the head check, and terminal markers are dropped only for a failed signature or binding. This lets a retry on a new commit reach `APPROVE`.
- Per slot the chain (all epochs, attempts 1..n, `prev_receipt_sha256` intact) is built from signature-valid, bound receipts first; the latest attempt decides and must be from the current epoch, otherwise the slot is unmet (soft). Earlier non-PASS attempts stay in `unresolved_findings`.
- Supervisor chain: `WORKER_LOST` is an informational finding; `BUDGET_EXCEEDED` and `RETRY_EXHAUSTED` are hard, never-waivable terminal markers; any other description is hard. Markers never count toward acceptance.
- TestRun: `expected_test_ids` must equal the manifest's required tests for the slot, every command argv must be in `allowed_commands`, and PASS acceptance is the union of the manifest tests' `acceptance` (not the receipt's claim). StaticAnalysis: `covered_rules` must include the slot's `required_rules`. IndependentReview: the receipt `author_principal` must equal the manifest's (normalized) and the reviewer must differ; `findings` surface as `review finding: ...`. Documentation receipts never contribute acceptance.
- Artifact binding: `artifact_resolver: Callable[[str], str | None] | None`. TestRun receipts with non-empty `artifact_digests` and no resolver give the hard reason `artifact digests present but no artifact_resolver` (default deny). With a resolver each `(path, digest)` must equal `artifact_resolver(path)`; a mismatch, None or a raising resolver is a hard reason and the slot is unmet. These checks run on the deciding receipt of a slot only.
- Waiver: valid only with a valid `operator_key`, a verifying signature, matching `task_id`, `epoch == current_epoch`, `head`, `manifest_sha256`, `current_epoch <= expires_epoch`, and coverage of EVERY unmet slot and acceptance id. Only soft reasons (unmet slots and acceptance ids) are waivable; hard reasons never are. A valid used waiver gives `APPROVED_WITH_WAIVER` with `waiver_record = record_id` and `human_approvals = [operator]`; an unusable waiver leaves the verdict MODIFY with an added reason.

## Known limits

- Event-chain edit, deletion and tail truncation are detected through the keyed HMAC chain and keyed anchor row. A per-run external anchor is supported, but rollback to an older internally consistent database copy is not detected when the matching external checkpoint is also unavailable or rolled back; compromise of `event_key` defeats the local authenticity boundary.
- The HMAC proves origin within the machine trust boundary (the holder of the key signed the receipt); it does not prove that the test run was honest or that recorded stdout, test ids or digests are true.
- S2 per-run WSL evidence demonstrates runner/signer separation for the recorded `run_manifest_commands` execution. It is not a persistent production deployment or a claim that every host/runtime is qualified. The operator attestation and sanitized runtime evidence are in `docs/sdlc/evidence/s2-e5-operator-attestation.json` and `s2-e5-runmanifest-wsl-280e2d0.md`.
- Reviewer receipts are authenticated with keys in the operator-signed registry and bound to the manifest, but the registry maps normalized principal strings to keys; it does not independently establish a human's real-world identity.
- After an epoch takeover, receipts from earlier epochs remain as history only; they never satisfy a slot in the new epoch.
- POSIX file/socket boundaries and selected WSL unit limits were exercised in the recorded WSL run. Windows Job Object nesting and prohibited process-kill/kill-table scenarios remain unverified (`NOT_RUN`). Full E8 crash/resume bake-off is also `NOT_RUN`; the current lifecycle fixture terminates a child process.
- The store's database/WAL/SHM permission hardening uses best-effort `chmod`; Windows ACL behavior was not established by the recorded WSL evidence.
- Simulated push/pull-request operations persist an append-only `PENDING` intent and later a completion event; their local Git subprocesses have finite command timeouts. A timeout remains pending and requires same-key/same-payload retry against the backend's durable idempotency binding. This updated path is pending a designated-agent regression run on its new code head.
