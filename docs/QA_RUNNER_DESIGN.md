# S4 QA runner implementation design

## Goal

Implement the S4 category runner and evidence envelope so the six declared lanes use native
pytest discovery, exact committed selectors, reproducible local inputs, and fail-closed test
accounting. Acceptance is defined by `docs/S4_QA_AUTOMATION_PLAN_2026-10-24.md` AC-1 through AC-17.

## Non-goals

No CI, mutation tests, dependency installation during a run, external service calls, test execution
during the coding phase, VST receipt-schema change, or claim that candidate/sandbox-dependent S3
acceptance has passed. The HTTP API lane remains unsupported because the repository exposes only
Python module APIs in `tools/vst/`.

## Design

- `docs/qa/categories.json` is the committed source of truth. Each test selector has one stable ID,
  a source path, one `primary_category`, and source-commit provenance. Regression is a separate
  aggregate reference to functional, integration, API, and E2E selector IDs.
- Registered IDs are function or unittest-method selectors. The pytest plugin records every
  concrete collected node ID and its final outcome, then maps each case to exactly one registered
  selector. A selector is emitted as `PASS <selector-id>` only when it expanded to at least one
  case and every case passed. Any failed, skipped, xfailed, uncollected, duplicated, or unmapped
  case prevents that selector from passing. Concrete IDs and outcomes remain in the report.
- `tools/qa/registry.py` validates the exact manifest schema, uniqueness, category membership,
  source files, source commit bindings, and current candidate HEAD binding. `tools/qa/run.py` is the
  single CLI. `tools/qa/pytest_plugin.py` captures collection and per-case outcomes. Report
  normalization and digest validation live in `tools/qa/report.py`; synthetic negative inputs are
  data fixtures consumed through unchanged VST product interfaces.
- The runner passes each distinct source module to pytest once and writes the expected selector IDs
  plus the full known selector map to an invocation-local selection file. The plugin deselects known
  selectors that are outside the requested category, including policy `NOT_RUN` rows; unknown items
  from those modules remain collected so the runner can report them as unexpected and fail closed.
  This keeps Windows process arguments bounded independently of the selector count while preserving
  expected-selector, unexpected-item, and uncollected-selector accounting.
- The runner invokes pytest as a child using a strict runtime profile: Windows CPython 3.14.3 at
  `C:\Python314\python.exe`, or POSIX CPython 3.12.3 in the dedicated WSL2 environment. The
  profile is derived from the running process; no caller-supplied interpreter fallback is allowed.
  Each profile uses an explicit isolated dependency target outside the repository and the same
  repository lock (`tools/qa/requirements.lock`). Pytest is pinned to 9.0.3: the official 9.0.3
  release supports Python 3.10+ and its PyPI advisory record lists no
  vulnerabilities, while 8.4.2's record identifies a UNIX temporary-directory vulnerability fixed
  in 9.0.3. The transitive test-only packages are pinned and wheel-hash-locked from the official
  PyPI JSON release records (`pytest`, `pluggy`, `packaging`, `iniconfig`, `Pygments`, `colorama`).
  This excludes source distributions and build-time dependencies. The runner never resolves
  or installs dependencies. Environment preparation creates an external target from the hash-locked
  wheel files already in the wheelhouse. `python -m tools.qa.prepare_dependencies --repo-root <repo> --wheelhouse <external-wheelhouse> --dependency-target <new-external-target>` verifies the selected purelib wheels against the lock and creates a new target without pip or network access; it never overlays an existing target. Each runner call supplies both `--dependency-target` and `--dependency-wheelhouse`. Before pytest, the runner verifies each wheel digest, metadata and `RECORD` against the lock, then requires an exact byte-for-byte target inventory derived from the verified archives. The report binds the selected wheel hashes and pre/post target-content digests. `PYTHONDONTWRITEBYTECODE=1` prevents generated bytecode from entering that inventory; a post-run verification must match the pre-run digest. Unsupported wheel layouts and any changed, missing, or extra file fail closed. The report explicitly says in-run immutability is `NOT_VERIFIED`: a same-identity process could change and restore a dependency between snapshots. The child process receives the verified target through `PYTHONPATH`, with user-site loading disabled. The runner applies a timeout,
  output cap, minimal environment, repository-relative selectors, and an exact candidate working
  directory. Git reads
  that need a worker-owned checkout use a per-invocation `safe.directory` value scoped to that
  canonical checkout; no global Git configuration is changed.
- The QA JSON report is an artifact, not a signed VST receipt. When invoked from the existing VST
  runner, selector-level `PASS` lines use the existing trusted pass-lines parser; the VST runner
  signs the standard receipt and binds the report digest as an artifact. This preserves the current
  receipt contract while retaining concrete pytest outcomes for audit.
- Reports contain relative artifact paths, exact candidate HEAD, registry hash, lock hash,
  selected wheel hashes and dependency-target content digest with pre/post verification state,
  runtime profile, interpreter/tool versions, command, exit status, expected selectors, concrete collected and
  executed node IDs, per-case outcomes, and a typed result. Output logs are append-only per
  category. Each report binds to the exact stdout/stderr byte ranges written by that invocation
  and their chunk hashes and sizes. Those exact per-run output metadata remain serialized and
  checked against the captured bytes, but are excluded from the cross-run semantic digest because
  pytest output may contain timing-dependent text. Byte offsets, run timestamps and prior append-only
  history are also excluded from that digest. The fixed
  paths are `docs/sdlc/evidence/qa/{category}.report.jsonl`, `{category}.stdout.txt`, and
  `{category}.stderr.txt` for all six categories. Environment values, credentials, and user-specific
  absolute paths are never serialized.

When a QA invocation runs through VST, its exact task manifest must explicitly include the three
output paths for that category in `change_scope.allowed_paths`. The manifest may additionally
include the exact source paths and lock path required for that task. This per-invocation declaration
does not widen or change VST diffgate rules. The runner rejects any output path other than the fixed
category paths.

New QA contract tests belong under `tests/qa/` and use the `test_s4_` filename convention. The
deterministic registry builder classifies those files into the matching S4 lane; seeded-failure
tests use `tests/qa/seeded_failure/` or the `test_s4_seeded_failure` prefix. Unknown test paths fail
registry generation rather than silently receiving a category.

### Platform acceptance matrix

The committed selector registry assigns each selector to Windows, unprivileged Ubuntu-24.04 WSL,
the restricted Ubuntu-24.04 root harness, or more than one of those runtime profiles. The runner
executes only selectors assigned to its exact profile. Selectors assigned elsewhere are not treated
as passes or skips in the current profile. The root harness can run only its two explicitly assigned
identity-isolation selectors; its versioned run-nonce-bound proof verifies a private network
namespace with only loopback and a working ephemeral loopback socket. A shell-free wrapper passes an
open parent namespace descriptor across `unshare --net`, validates its `net:[inode]` target, and
binds that inode into the proof; the restricted runner compares it with the current namespace
without reading `/proc/1/ns/net`. The helper source in the repository must be installed at the fixed
root-owned, non-group/world-writable `/usr/local/libexec/vst-s4-root-harness.py` path and invoked
with isolated Python (`-I`). It uses fixed system executable paths and imports no candidate module
before `setpriv` drops the bounding set. With no non-loopback interface and no `CAP_NET_ADMIN`, external
egress is structurally unavailable without an external canary request. This is local QA evidence,
not an S2 worker receipt or independent approval.

Every WSL candidate must resolve beneath the distro-local `/tmp/vst-s4-candidate` root. The runner
scans `/proc/self/mountinfo`, rejects Windows-drive `drvfs` or `9p` sources and any `drvfs`/`9p`
mount covering the candidate, and permits unrelated WSL `9p` mounts. Reports bind the canonical
candidate path and mount-table SHA-256. The matrix requires all WSL reports to share the same
candidate path and checks that the root proof agrees with its report.

The runner and matrix normalize CRLF to LF before hashing the dependency lock, so equivalent Windows
and POSIX checkouts bind to one digest; bare carriage returns are rejected. The matrix combines
per-profile reports only when candidate HEAD, registry hash, lock hash,
artifact integrity, and runtime identity agree. It rejects missing profile reports, stale or
duplicate selector outcomes, any assigned selector that is failed/skipped/`NOT_RUN`, incomplete
capture, or unexpected nodes. Matrix approval requires every committed selector to pass on every
profile assigned to it. The full design and WSL transfer/preflight constraints are in
`docs/sdlc/S4_POSIX_RUNTIME_MATRIX_DESIGN.md`.

## Failure modes

Unknown or duplicate selectors, stale candidate/registry provenance, absent runtime profile or
locked dependency, zero-case selectors, unmapped cases, incomplete collection, timeout, truncated
output, or any non-passing required assigned case produce a typed non-approving report and a
non-zero command exit. The matrix is non-approving if any required profile evidence is absent or
does not bind to the same candidate/registry/lock. No empty-success fallback or interpreter
fallback exists.

## Rollout and rollback

Add the runner and registry as new modules without changing existing VST receipt validators. The
initial rollout is local and synthetic. Rollback removes the S4 category slots/callers and new QA
modules; existing VST runner behavior and v1/v2 contracts remain unchanged.

## Test plan

After all S4 code is committed, `functional-test-reviewer` authors/runs focused registry, mapping,
normalization, and non-approving-result cases. `e2e-runner` then runs each native category and the
aggregate regression/seeded-failure flows through isolated temporary repositories. Tests are
mapped to AC-1 through AC-15; candidate comparison and fresh sandbox-bound cases remain `NOT_RUN`
until their exact external prerequisites are satisfied. No tests have been run for this design.

## Unknowns and ownership

iniconfig 2.3.0, Pygments 2.20.0, and colorama 0.4.6. QA runs will use the new hash-pinned
pytest 9.0.3 lock in an isolated target, not the pre-existing pytest installation. The operator is
accountable for the delegated sprint; Codex coordinates implementation. PyPI exact-release pages:
