# S4 QA runner technical design

## Goal

Bind every native QA category run to a reproducible, exact-head VST `TestRun` receipt without changing existing v1/v2 signed bytes or consuming S5's planned v3 static-analysis provenance.

## Non-goals

- No CI, mutation testing, provider/network calls, live service, external repository, or product-source fault injection.
- No HTTP API is claimed. API coverage means the existing Python module surface.
- No independent QA authority or phase state machine is introduced.

## Design

- The committed `docs/qa/categories.json` is the canonical static category and test-ID inventory. It records one primary category, committed pytest node-ID selectors, source-commit provenance, test-owner role, and explicit partial/`NOT_RUN` states. The registry source head and every supported category source head must be ancestors of the candidate HEAD. `regression` is an aggregate over functional, integration, API, and E2E IDs and does not assign a second primary category.
- Each run supplies a run-specific VST v2 task manifest. Before execution, the runner requires the manifest's `TestRun` slots, required test IDs, and exact pytest argv selectors to equal the supported projection of `categories.json`. The registry itself is a predeclared signed artifact; its SHA-256 is written in the report. The receipt's current candidate HEAD is separate from the registry's source-provenance HEAD.
- The QA entry point uses `tools.vst.runner.run_manifest_commands` and the existing v2 `TestRun` contract. The signed request binds manifest digest, candidate HEAD, allowed command, parser-derived outcomes, and artifact digests. It never trusts a caller-provided result or collected-ID list.
- Exact category commands disable pytest's cache provider (`-p no:cacheprovider`) and report-bound child processes set `PYTHONDONTWRITEBYTECODE=1`; these avoid writes to the read-only source snapshot from pytest cache and Python bytecode generation. The report records these variable names without copying values.
- The QA runner is POSIX-only and targets the named `Ubuntu-24.04` WSL runtime, CPython 3.12.3 and pytest 7.4.4. It fails closed on Windows or any other runtime. The Windows `C:\Python314` interpreter named in the original plan is not compatible with the existing v2 signer boundary and is superseded by observed WSL inventory evidence.
- `tools/qa/wsl_snapshot.py` transfers a clean, committed branch as a bounded self-contained Git bundle over `wsl.exe` stdin, then verifies the exact cloned HEAD and independently computed bundle digest. The destination root is pre-provisioned runner-owned mode `2710` with the worker group; each snapshot is isolated, private to the runner except worker traversal/read of the clone, and nonwritable to the worker. This transfer tool does not provision the distro, install packages, run pytest, or provision the signer.
- On POSIX, when a run requests a distinct worker UID/GID, `_run_one()` starts the trusted `tools/vst/worker_exec.py` trampoline after the OS credential switch and before the manifest-authorized argv. The helper verifies real/effective/saved UID and GID plus empty supplementary groups, enables `PR_SET_NO_NEW_PRIVS`, clears ambient/effective/permitted/inheritable capabilities, verifies that state, and then `execvpe`s the original argv. Capability-bearing runner units must not launch manifest commands directly: a probe at base HEAD `0aa7a53` showed that the worker could otherwise retain `CAP_SETUID` and regain UID 997. This remediation remains pending runtime verification on a fresh snapshot.
- Emit a canonical machine-readable QA report plus bounded stdout/stderr integrity-reference artifacts. The references contain output hashes, byte counts, and capture status, not raw test output. The report records schema version, category/slot, registry and VST manifest digests, source and candidate HEADs, dirty state, interpreter/runtime and lock identity, argv, duration/exit result, expected/collected/executed/skipped/xfail/unexpected IDs, artifact digests, and typed state. Paths are repository-relative; environment values and secrets are not copied.
- The exact per-run report, event, and stream-reference paths are excluded from candidate source-diff evidence only after pre-run validation that each is predeclared, untracked, absent, contained, and unique. Their bytes remain individually included in the signed v2 artifact digests. Any other generated/untracked path remains part of candidate diff scope and can fail the VST diff gate.
- `docs/qa/seeded_failures.json` is a bounded committed catalog. Each supported fixture binds a stable ID, canonical JSON input and its SHA-256 (up to 16 KiB), expected rejection code, and exactly one required pytest node ID. Seeded-failure test bodies call `record_seeded_failure_observation()` from the pinned pytest plugin after exercising unchanged product code. The plugin records the fixture ID, input digest, expected and observed rejection codes, and test ID. Both the run CLI and report-bound runner reject duplicate JSON keys and validate the catalog's exact schema/state; the report-bound runner also requires fixture test IDs to equal the manifest slot's complete required-ID set after metadata validation and before command execution. Missing, duplicate, extra, or mismatched observations cannot produce a passing report. The catalog itself is a predeclared signed artifact. The initial catalog stays explicitly `NOT_RUN` and empty until test owners add concrete fixtures and linked tests.
- The authoritative gate remains `tools.vst.gate.evaluate`. It must receive the v2 receipt, exact current HEAD, and an artifact resolver that recomputes the report digest. Existing gate rules reject stale HEAD, missing/skipped required IDs, invalid signatures, and missing/hash-invalid deciding artifacts. Unsupported or `NOT_RUN` categories have no passing receipt and remain unmet; waivers remain only those permitted by ADR-0001.
- Seeded-failure IDs are ordinary manifest-required tests. A passing test means unchanged product code returned the expected rejection; its report artifact includes fixture ID and input digest.

## Failure modes

Unknown category, selector/manifest mismatch, duplicate/missing/unexpected IDs, skipped/xfail required IDs, wrong interpreter, changed lock/registry/fixture catalog, command failure, malformed parser/event output, missing artifact, digest mismatch, stale HEAD, fixture observation mismatch, or invalid signature is typed and non-approving. Structurally valid failures remain v2 `FAIL` where `derive_result()` supports it; zero executed test IDs remain `INCONCLUSIVE` under that contract. Report and receipt outcomes must agree before the signer is called. Partial registries cannot produce signed passing receipts. No fallback interpreter, install, download, empty-success result, or silent category substitution is allowed.

## Rollout and rollback

Introduce the runner and report artifact as new S4 paths. Preserve existing v1/v2 schema and signatures. If report construction or signing fails, do not append a receipt; the category remains unaccepted. A structurally valid failing run may produce a signed `FAIL` receipt, which is non-approving. Roll back by removing the new runner and registry projection; no database migration or state conversion is needed.

## Test plan

After all S4 source coding: functional tests cover manifest/category mapping, parser accounting, report canonicalization, fixture input hashing and fixture-observation mismatches. The local E2E fixture selectors cover native pytest discovery and v1 runner-to-gate receipt/artifact digest binding, exact-head acceptance, and stale/missing/corrupt artifact rejection. They do not cover `tools.qa.run` report serialization or v2 signed report artifacts; that report-bound selector is an explicit denominator gap, separate from the trusted signer socket and deployed sandbox runtime gates. Only the designated functional and E2E agents author/run these tests. No tests are run during coding.

## Unknowns and ownership

- The S4 plan does not identify a canonical technical service owner for the runner or lock; owner remains `UNKNOWN`. Operator is accountable under delegated sprint work; Codex coordinates and `implementation-engineer` executes.
- Named WSL inventory reported CPython 3.12.3, pytest 7.4.4, iniconfig 1.1.1, packaging 24.0, and pluggy 1.4.0; pytest-asyncio is absent and no current test uses asyncio markers. The hash-pinned lock records pytest plus its required runtime dependencies. No dependency installation is authorized in this source slice.
- The Windows checkout-to-WSL snapshot transfer is implemented in `tools/qa/wsl_snapshot.py` and was executed for fresh run `f3ad62c94bc0429987bc24277103d5b4` at source HEAD `56dce67e508ccf452b2b7b39ed7f33c863081269`. The worker read-only boundary and seven mapped POSIX E2E selectors passed; this does not prove the report-bound signer path. That path remains `NOT_RUN` until the trusted signer socket and run-specific v2 manifest are available inside the named WSL environment. The transfer/system owner is not established in repository records.
- The gate validates the signed receipt and artifact digest, while the trusted runner/parser produces the report. It does not independently interpret arbitrary QA report JSON; this trust boundary must stay explicit.
- The local E2E fixture selectors added in change 0189 use the existing v1 local `run_and_sign` helper and synthetic HMAC receipt fixtures. They prove those fixture boundaries only. No E2E selector currently drives `tools.qa.run` through v2 report serialization/signing; that is why the category denominator remains `PARTIAL`, independently of the external trusted signer socket and sandbox runtime availability.
