# Change record 0020: S1 second remediation (store, runner, slice)

## What changed
- `tools/vst/store.py`:
  - Schema version 3: new column `leases.receipt_count`, new event kind `LEASE_EXPIRED_PARTIAL`. Version 2 databases are refused (not migrated).
  - Retry cap counts only worker-attributed failures: `failed_attempts(task_id)` = max over worker slots of FAIL/INCONCLUSIVE receipts + EXPIRED leases that wrote nothing (WORKER_LOST). Fenced leases (epoch takeover) and released leases are not counted, so a takeover cannot exhaust the cap. `acquire_lease` refuses at `failed_attempts >= retry_cap + 1` (RETRY_EXHAUSTED marker, kind `retry`). Lease attempts stay previous + 1; receipt attempts stay consecutive per slot chain.
  - Budget: `register_task` seeds the budget row from the manifest `cost_cap`; `set_budget` needs a registered task and refuses a cap above `cost_cap`; `acquire_lease` and `append_receipt` refuse when `spent >= cap` or a BUDGET_EXCEEDED event/marker exists; `charge(task_id, amount, *, supervisor_key, runner_id)` commits the BUDGET_EXCEEDED event and the signed marker itself before raising `budget`; `mark_budget_exceeded` stays idempotent (shared helper).
  - Event anchor: before every event append the anchor MAC, `count == COUNT(*)` and `head == last hash` are verified; mismatch raises `StoreError(kind='integrity')`, nothing is recomputed, the silent COUNT(*) fallback is gone. `verify_event_chain`, `event_anchor` (now returns the verified pair), `render_state_md` and the new `failed_attempts` read inside one explicit read transaction.
  - `OPERATOR_ACTION` removed from `CALLER_EVENT_KINDS` (callers keep `NOTE`). A `supervisor_key` equal to the `event_key` is refused with kind `key` by `acquire_lease`, `charge`, `append_supervisor_receipt`, `supervisor_reap_and_mark`, `mark_budget_exceeded`.
  - A lease that wrote at least one receipt and then expired records `LEASE_EXPIRED_PARTIAL` (attempt, lease_id, receipts) next to `LEASE_EXPIRED`; still no WORKER_LOST marker.
- `tools/vst/runner.py`: `extra_env` keys shadowing `ENV_ALLOWLIST` names, `PATH`, `PYTHONPATH`, `PYTHONSTARTUP`, `PYTHONHOME`, `PYTEST_ADDOPTS`, `PYTEST_PLUGINS`, `LD_PRELOAD`, `LD_LIBRARY_PATH` or `DYLD_*` (case-insensitive) raise `ContractError` before anything runs. On Windows the process tree is killed after a normal exit too (`taskkill /T /F`, failures ignored). A reader thread still alive after the join, or a read error, gives exit code -4 (`EXIT_CAPTURE_INCOMPLETE`) for that command and `report['capture_incomplete'] = True` (also per command).
- `tools/vst/slice.py`: `budget_exceeded` uses the new `charge` signature and also reports the marker written by `charge` and the refused `begin`; three new scenarios `retry_across_head_change`, `worker_lost_before_first_receipt`, `takeover_does_not_exhaust_retry_cap` (17 total). Their expected verdicts rely on the new gate rule (head and artifact checks only on the deciding attempt, supervisor markers exempt from the head check) owned by the contracts/gate change.
- `tools/vst/schemas/README.md`: Store, Runner and Slice sections updated.

## Why
Second S1 re-review of 3e27720 (core/DECISION_LOG.md, "S1 re-review of 3e27720"): a takeover or an unattributed fenced lease consumed the retry cap; the budget row was never seeded from the manifest and a task could keep running past its cap; the event anchor was recomputed silently (a tampered log could be re-sealed) and verified outside a snapshot; a caller could forge operator action events; the event key could double as the supervisor key; partial work of a dead lease left no trace; `extra_env` could re-point loaders; stray Windows descendants and incomplete captures were not fail-closed.

## Affected contracts and paths
Breaking Python API: `charge(task_id, amount, *, supervisor_key, runner_id=...)`; `set_budget` requires a registered task and cap <= manifest cost_cap; `record_event` accepts only `NOTE`; `event_anchor()` may raise `StoreError(kind='integrity')`; new `StoreError` kinds `key` and `integrity`; `SCHEMA_VERSION` 3; new public `Store.failed_attempts`; new constants `EXIT_CAPTURE_INCOMPLETE`, `FORBIDDEN_ENV_NAMES`, `FORBIDDEN_ENV_PREFIXES`. Behavioral: a task whose `cost_cap` is 0 or fully spent can no longer acquire a lease or append a worker receipt. Paths: `tools/vst/store.py`, `tools/vst/runner.py`, `tools/vst/slice.py`, `tools/vst/schemas/README.md`. Tests under `tests/vst` that call `charge`, `set_budget` before `register_task`, `record_event(... "OPERATOR_ACTION" ...)`, use `user_version` 2, tamper with `meta` and expect recomputation, or assert exactly fourteen slice scenarios must be updated by the test agents.

## Verification state
Code changed only. Tests were NOT run or rerun by design; nothing was imported or executed (no Python, no sqlite). Not independently reviewed. Open point: on Windows the post-exit `taskkill /T` targets a pid whose root has exited, so descendant discovery and pid-reuse safety are best effort.
