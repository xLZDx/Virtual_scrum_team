# U5-2: apply AEVE patch proposals through the diff gate

Module: `tools/vst/patch_proposals.py`. Tests: `tests/vst/test_u5_patch_proposals.py` (written, **NOT_RUN**: running tests is forbidden by the operator for this sprint, so no result is claimed; no code was executed while writing this).

Decision OD-8 (operator, 2026-11-08): AEVE's repair lab proposes bounded patches and never applies one; VST applies them in the isolated worktree and the diff gate checks them; the model writes code only for what AEVE proposed no patch for. Depends on U5-1 (`tools/vst/worker_gate.py`) and U1-5 (`tools/uc/adapter.py`).

## What AEVE really provides (AEVE origin/main, read-only via git)

- `src/aeve/repair/patch.py:22` `SCHEMA_VERSION = "g6.patch.v1"`; `:225` `propose_patches_report(snapshot)` builds the document.
- Document keys: `schema_version`, `proposals`, `proposal_count`, `llm_calls` (always 0), `executed_project_code` (always false), `note`, optional `status: "PARTIAL"` and `uncovered`, and `report_sha256` (sha256 of the canonical JSON without that key: `json.dumps(..., ensure_ascii=True, sort_keys=True, separators=(",", ":"))`, `patch.py:245-248`). **`report_sha256` is an integrity check, not authenticity**: anyone who can write the document can recompute it. It detects accidental damage only.
- One proposal (`patch.py:25-37`): `{file, recipe, detail, diff, changed}`. Recipes: `trailing-whitespace` and `final-newline` carry a diff and `changed: true`; `unused-import`, `unsupported-language`, `encoding-skip`, `parse-error` are notes with `changed: false` and an empty diff. Several proposals for one file are chained: `final-newline` is computed on the output of `trailing-whitespace` (`patch.py:196-208`).
- The diff is a per-file unified diff made by `difflib` on `str.splitlines()` (`patch.py:143-172`): headers `--- <file>` and `+++ <file>` without `a/`, `b/` and without a `diff --git` line, three context lines, no trailing newline, secrets redacted to `[REDACTED]`.
- **No base identity**: the document has no head, no file hash and no snapshot hash. **No bounds field**: the only bounds are the hunks themselves. The repair package (`src/aeve/repair/__init__.py`) states it never applies patches.
- **No CLI**: `aeve review` runs only the `g6.python-diagnose` and `g6.python-deadcode` executors (`src/aeve/review.py:1638-1657`); no command or executor emits `g6.patch.v1`. The adapter `tools/uc/adapter.py` (`run_review`) therefore cannot obtain proposals and was not extended. This module takes the JSON document as input (bytes or parsed object) and validates it against the schema above.

- `check_model_changes(*, model_changed_paths, apply_result=None, proposal_patched_paths=None, override_reasons=None, authorized_by=None) -> ModelChangeVerdict`.

## Verdicts

| Verdict | Meaning |
|---|---|
| ACCEPTED | document valid, base matches, patches applied, the real resulting diff passed `gate_worker_change`, the worktree holds exactly the candidate bytes (re-read and compared) |
| REFUSED | `STALE_BASE` (head differs, or git says the patch does not apply or does not match the index), out-of-scope or protected path or any other gate refusal, `DIFF_PATH_MISMATCH`, model change on a patched path (`MODEL_OVERRIDES_PROPOSAL`, `OVERRIDE_REASON_INVALID`, `OVERRIDE_AUTHORIZATION_MISSING`) |
| BLOCKED | malformed, oversized, redacted or hash-mismatching document, `RECIPE_MISMATCH`, no patch in the document, `PATCH_NOT_REPRESENTABLE`, `PATCH_DOES_NOT_APPLY`, `UNTRUSTED_GIT_CONFIG`, `WORKTREE_LOCKED`, `JOURNAL_PRESENT`, `DIRTY_WORKTREE`, `GIT_UNSAFE_DIRECTORY`, git failure or timeout, no effect, write failure (rolled back or `ROLLBACK_CONFLICT`), any exception |

## Flow and where the worktree is touched

1. `VALIDATE`: strict schema check. Unknown keys, wrong schema version, `llm_calls != 0`, `executed_project_code != false`, count or hash mismatch, non-canonical or glob paths (`worker_gate.path_hazards`), unknown recipe, a note with a diff, a patch recipe without one, headers not naming the file, hunk counts not matching the `@@` header, a `[REDACTED]` marker, NUL, duplicate patch recipe per file, duplicate JSON keys, NaN: all BLOCKED. Caps: document 4 MiB, 256 proposals, 512 KiB per diff, 4 MiB of diffs, 128 patched files.
   **Recipe check (`RECIPE_MISMATCH`)**: the recipe is a label, so the diff must do what the label says (mirrors `patch.py:57-115`). `trailing-whitespace`: every hunk has equal old and new line counts and, position by position, the new line is the old line with trailing spaces and tabs removed, at least one line changes, no end-of-file marker. This accepts the shape difflib really produces (a block of `-` lines then a block of `+` lines, or an unpaired removal, context and addition for repeated lines) and refuses anything that changes code. `final-newline`: exactly one hunk that is either the marker form of `patch.py:_diff` (context lines, then `-last`, `\ No newline at end of file`, `+last` with the same text) or only removals of empty lines after the context. For one file `final-newline` must follow `trailing-whitespace`. A false refusal is possible when difflib aligns repeated lines so that a hunk changes its line count; it is BLOCKED, never applied.
2. `BASE_HEAD`: `proposal_base_head` (the head AEVE analysed, caller-reported, for example the `head` of the AEVE review response of the same run) must equal `base_head`, else REFUSED `STALE_BASE`.
3. `PRESCREEN`: the claimed diff (canonical `diff --git` form) goes through `worker_gate.gate_worker_change` with a derived placeholder candidate id. A REFUSED or BLOCKED answer ends the run before any git call. Scope, protected paths and path hazards are decided by the U5-1 gate, not re-implemented.
4. `WORKTREE_CHECK`:
   - **Lock**: `.git/vst-u5-2.lock` is created with `O_CREAT|O_EXCL` in the git-dir (for a linked worktree, its own git-dir) and removed in `finally`; present means BLOCKED `WORKTREE_LOCKED`. A lock left by a killed process must be removed by the operator. A journal left by a failed write (see below) is BLOCKED `JOURNAL_PRESENT`.
   - **Trusted repository**: the git-dir and common-dir are derived from the `.git` entry itself (a directory, or a one-line `gitdir:` pointer file; links and special files are refused) and the git-dir must be the common-dir or lie under `<common-dir>/worktrees`. Then, reading files directly without git, the repository config, `config.worktree` and `info/attributes` (and every `.gitattributes` from the worktree root down to each patched file's directory) must not hold: a `filter` section, `include`/`includeIf`, any `extensions` entry, a `diff "<driver>"` section, `attributesFile`, `hooksPath`, `fsmonitor`, `worktree`, `textconv` or `command` keys; attributes `filter`, `ident`, `working-tree-encoding`, `crlf` or `export-subst` (in any state or spelling of case), `diff=<value>` or `merge=<value>` (a driver name; the plain `diff`, `-diff`, `merge`, `-merge` forms select no driver and pass), and any `text` or `eol` in a form other than `text`, `-text`, `!text`, `text=auto`, `eol=lf`, `eol=crlf`, `-eol`, `!eol`. Operator decision of 2026-11-11 (register item R-27): the line-ending attributes `text`, `eol`, `-text` and `text=auto` describe a file and do not run code, so they no longer block; the check is a token scan of the attribute part of each line (the pattern, quoted or not, is dropped; macro `[attr]` lines are scanned the same way; a quoted pattern that is unterminated or holds a backslash is refused, because git falls back to an unquoted pattern on a bad escape; lines are split at LF only and blanks are exactly space, tab and CR, so a file holding ``, ``, ``-``, U+0085, U+2028 or U+2029 is refused; a repository config `[attr]` section, which can name an unscanned attribute source via `attr.tree`, is refused too). Any other hit is BLOCKED `UNTRUSTED_GIT_CONFIG`. The MATERIALIZE stage writes the patched bytes directly, so a line-ending attribute does not change what is written; whether `git apply --cached` of a CRLF-normalized index entry stays consistent is NOT_RUN. `git rev-parse --git-dir --git-common-dir` must agree with the derived directories.
   - Every git call also carries `-c core.attributesFile=<null device> -c core.hooksPath=<null device> -c core.autocrlf=false -c core.safecrlf=false -c core.quotepath=false -c core.fsmonitor=false -c commit.gpgsign=false --literal-pathspecs` (`GIT_PREFIX`) and a fixed minimal environment.
   - `git rev-parse --show-toplevel` equals the isolation worktree root; `HEAD` equals `base_head` (else REFUSED `STALE_BASE`).
   - **Clean**: `git status --porcelain -z --untracked-files=no -- <patched paths>` is empty, `git ls-files -v` shows tag `H` for every patched path (assume-unchanged `h`, skip-worktree `S`/`s`, untracked and others are BLOCKED `DIRTY_WORKTREE`), and, in Python, each worktree file equals `git cat-file blob <base>:<path>` byte for byte.
   - **Representable base**: AEVE built its diffs from `str.splitlines()` of a BOM-stripped decode. A base blob that starts with a UTF-8 BOM, is not UTF-8, or contains `\r`, `\x0b`, `\x0c`, `\x1c`, `\x1d`, `\x1e`, `\x85`, ` ` or ` ` cannot be matched by such a diff: BLOCKED `PATCH_NOT_REPRESENTABLE` (a clear cause instead of a misleading `STALE_BASE`). CRLF files are therefore not supported.
5. `BUILD`: the scratch directory holds a throw-away index (`GIT_INDEX_FILE`) **and a scratch object directory** (`GIT_OBJECT_DIRECTORY`, with `GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing at the repository's objects), so no blob, tree or commit object lands in the repository; it is deleted in `finally`. `git read-tree <base>`, then each patch in document order: `git apply --check --cached` and `git apply --cached` (`--include=<file>`). Exit-1 mapping of the check: stderr matching `patch does not apply`, `patch failed` or `does not match index` is REFUSED `STALE_BASE` (the base is not what the patch needs); any other exit 1 (`does not exist in index`, no valid patches, fragment without header, corrupt patch, symlink) and any exit of 128 or more is BLOCKED `PATCH_DOES_NOT_APPLY` with an ascii stderr tail of 200 characters; `dubious ownership` is BLOCKED `GIT_UNSAFE_DIRECTORY`. `git write-tree` and `git commit-tree -p <base>` (fixed identity and dates, no signing) create the candidate; `git diff <base> <candidate>` (no renames, no external diff or textconv) gives the diff bytes and changed paths; the candidate bytes are read with `git cat-file blob`. Because its objects live only in the scratch directory, `candidate_head` is an identifier for the content; it cannot be resolved after the call, which is the price of leaving no dangling objects. `candidate_tree` is returned as well.
6. `GATE`: `gate_worker_change` runs on the real diff and the candidate id. Anything but ACCEPTED ends the run; the worktree was never written.
7. `MATERIALIZE` (the only stage that writes; git does not write, so no smudge filter, hook or attribute can run):
   1. Under the lock, the clean check (byte comparison with the base blobs) and the gate (which includes the link and reparse-point check) are repeated immediately before the write.
   2. A journal `.git/vst-u5-2.journal` (`O_EXCL`; path, base sha256 and candidate sha256 per file) is written and synced.
   3. Each file is written with a temp file in the same directory, flush, fsync and `os.replace` (retried briefly because Windows may refuse it).
   4. Each file is read back and compared with the candidate bytes (`post_materialize_verified`).
   5. Any exception, including `KeyboardInterrupt` (`BaseException`), triggers a **compare-and-restore** rollback: a path is restored to the base bytes only if it still holds the candidate bytes; a path that holds anything else is left alone and reported as `ROLLBACK_CONFLICT` (BLOCKED, `worktree_state = UNKNOWN`, journal kept so the next call is `JOURNAL_PRESENT`). A clean rollback removes the journal and reports `ROLLED_BACK`. The exception is re-raised if it was not an `Exception`. The journal is removed after a successful write.

Retry and crash behaviour: a failure before `MATERIALIZE` leaves the worktree byte-identical because nothing was written. A crash during `MATERIALIZE` leaves the journal (and a stale lock); the next call is BLOCKED and the operator inspects or discards the worktree. A retry after ACCEPTED is BLOCKED `DIRTY_WORKTREE`. Two concurrent calls on one worktree: the second is BLOCKED `WORKTREE_LOCKED`.

Every git call: `shell=False`, an absolute git path found by `find_git` (absolute `PATH` entries only, never inside the worktree, never the current directory; same rule as `tools/uc/aeve_probe.py`), `cwd` = worktree, explicit timeout (default 30 s), output capped at 16 MiB.

## Isolation evidence wording

The gate runs before the files are written, so its isolation proof is `isolation_stage: "pre_materialize"`. The context passed to it has `worktree_head` set to the candidate commit id: a placeholder, because the real HEAD of the worktree is unchanged and not the candidate. `ApplyResult.to_dict()` adds `isolation_stage` and a `worktree_head_note` to the proof saying exactly that. The property `worktree_head_matches_candidate` is therefore `CALLER_ASSERTED` and says nothing about the real HEAD. The post-write evidence is `post_materialize_verified` (`true` only after every file was re-read and equals the candidate bytes) and `file_digests`. This module does not move HEAD or the index; the change appears as an unstaged modification.

## What is reused from worker_gate

`gate_worker_change` (three times: claimed diff, real diff, re-check before the write), `IsolationContext`, `path_hazards`, `parse_diff_paths` (also inside `hunk_counts_from_diff`), `MAX_CHANGED_PATHS`, the verdict constants. `tools/vst/diffgate.py` and `worker_gate.py` are not changed. Not available there: a way to gate a diff before a candidate exists (hence the placeholder candidate in `PRESCREEN`) and a public protected-path matcher (reached only through the gate).

## Share of change by origin

`change_origin_share(proposal_lines_by_file, model_lines_by_file)`: each argument maps a path to a list of hunks, each hunk an `(added, deleted)` pair. Result: `proposal` and `model` blocks with `added`, `deleted`, `lines` (= added + deleted), `hunks`, `files`; `total_lines`; `proposal_fraction` and `model_fraction` (`None` for an empty change); `files_touched_by_both`, `proposal_only_paths`, `model_only_paths`. Rule: attribution is by hunk; each hunk belongs to one origin, so a file touched by both contributes its proposal hunks to the proposal and its model hunks to the model; hunks must be disjoint. Paths match case-insensitively. Invalid input raises `ValueError`. Proposal hunks come from `ApplyResult.hunks_by_file` (counted on the real git diff); model hunks from `hunk_counts_from_diff` of the model diff.

`build_run_record(apply_result, model_hunks_by_file, overrides=None)` returns the JSON-able per-run record: verdict, stage, worktree state, `report_sha256`, `candidate_head`, `diff_sha256`, `partial`, `post_materialize_verified`, `patched_paths`, `no_patch_paths`, `proposal_lines`, `model_lines`, `total_lines`, both fractions, `files_touched_by_both`, `model_only_paths` and the recorded overrides. Proposal lines count only when the verdict is ACCEPTED and `post_materialize_verified` is true (`applied: true`). For every REFUSED or BLOCKED result, including BLOCKED after the gate accepted the diff (`DIRTY_WORKTREE`, `JOURNAL_UNAVAILABLE`, `MATERIALIZE_FAILED`, `ROLLED_BACK`, `ROLLBACK_CONFLICT`), the applied proposal lines are zero and the fractions use zero. The built-but-not-applied counts are reported separately as `attempted_proposal_hunks` and `attempted_proposal_lines`, and never enter the fractions. The verdict says why. Storing the record is the job of the pipeline store (U5-3).

## The model may not override a proposal

`check_model_changes` refuses a model change on any path with a patch in the document (`MODEL_OVERRIDES_PROPOSAL`). The patched paths are bound to the run: pass `apply_result` and they come from `apply_result.patched_paths` (the validated document, also when that apply was refused); `proposal_patched_paths` is an unbound alternative and exactly one of the two is required. Paths AEVE only flagged (`changed: false`) have no patch and are free for the model.

An explicit override needs three things for the exact path: `override_reasons[path]` (10 to 500 characters after trimming), a non-empty `authorized_by` (1 to 100 characters, the operator identity string supplied by the caller; it is recorded, not authenticated here), and at most 16 overrides in one call (else BLOCKED `OVERRIDE_CAP_EXCEEDED`). Text with Unicode categories Cc, Cf, Zl or Zp is rejected, so recorded text is plain printable text. The result lists `overrides` as `{path, reason, authorized_by}` and a `MODEL_OVERRIDE_RECORDED` reason. A missing or invalid authorizer keeps the refusal (`OVERRIDE_AUTHORIZATION_MISSING`), an invalid reason keeps it (`OVERRIDE_REASON_INVALID`), and an override for a path that is not in conflict is BLOCKED (`OVERRIDE_WITHOUT_CONFLICT`). An override only lifts this rule: the model change still goes through `worker_gate` for scope and protected paths.

## Limits (not verified or not covered)

- Nothing was run. The git commands (`apply --cached`, `commit-tree`, `ls-files -v -z`, `cat-file`, `GIT_OBJECT_DIRECTORY` with alternates, `GIT_CONFIG_GLOBAL` set to the null device on Windows) are written from the git documentation and unproven here.
- A stale base is detected by the caller-reported head, the worktree HEAD and `git apply` content matching. AEVE gives no file hashes, so a base that differs only outside the hunk context is not detected.
- CRLF, BOM, non-UTF-8 and splitlines-only-separator sources are refused; files without a final newline work only for the marker form.
- The config scan is a text scan, not a git config parser; it can refuse a harmless repository (fail closed). Global and system git config are not read (`GIT_CONFIG_NOSYSTEM`, null global).
- The per-worktree lock is advisory and cooperative: it stops two `apply_proposals` calls, not a human or the model editing files. The byte re-check right before the write narrows the window but cannot close it.
- `authorized_by` is a caller string; this module does not authenticate it.
- No OS sandbox or process containment, same as U5-1. AEVE has no command that emits the document; its production and transport are outside this task.
