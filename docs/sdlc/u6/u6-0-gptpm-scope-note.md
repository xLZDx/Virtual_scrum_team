## What changed

- `ReviewLoopResult` has a new last field `changed_paths_sha256: str | None = None` (default keeps old constructor calls valid) and `to_dict()` exposes it. The constructor guard refuses a value that is not None or 64 lowercase hex, and refuses a CLEAN result without one. The loop sets it from its input; when iterations exist it takes the digest from the last stored or recorded review facts (for a replay, the stored fact). The replay already cross-checked every stored fact against the input (`RESUME_MISMATCH` otherwise); `result()` additionally fails closed (`INTERNAL_ERROR`, BLOCKED) if the two ever differ. A BLOCKED result carries the input digest, or None when the input was malformed.
- `final_package.build_final_package` computes `uc.contracts.changed_paths_sha256(changed_paths)` (sha256 of the compact JSON of the sorted path list; it sorts, so order is irrelevant) and refuses with the new code `REVIEW_PATHS_MISMATCH` when `review_results.changed_paths_sha256` is missing, not 64 lowercase hex, or different. Missing is refused, never skipped. The reason is listed next to other refusals; details are fixed text.
- The package records the digest in `diff.changed_paths_sha256` and `review.changed_paths_sha256`. `verify_package_current` recomputes the digest from `diff.changed_paths` and reports `PACKAGE_INCONSISTENT` for either recorded value that differs or is absent (independent of the `package_sha256` check, which still reports `PACKAGE_TAMPERED`). `render_scope_note` lists "Reviewed paths sha256".

Signature changes: `ReviewLoopResult(..., replayed=False, changed_paths_sha256=None)` (new optional last field); `final_package._review_section(raw, story_id, head, replay_verified, paths_digest, refusals)` (private, new parameter); `build_final_package` and `verify_package_current` keep their signatures; new constant `final_package.REVIEW_PATHS_MISMATCH`; new import `from ..uc import contracts as uc_contracts` in final_package (review_loop already had it).

## Behavior notes

- A review result produced before this change (no `changed_paths_sha256`) is now REFUSED by the builder. That is intended.
- Packages built before this change fail `verify_package_current` (`PACKAGE_INCONSISTENT`, digests absent). No stored packages exist in the repository.

## Limits

- The binding proves the review was run against the digest of the packaged `changed_paths`; it does not prove who produced the review result (unsigned, caller-supplied). `changed_paths` is tied to the diff bytes by the existing `PATHS_UNDERSTATED` / `PATHS_EXTRA` checks.
- The digest covers the path list only, not file contents; head equality and the diff digest cover contents.
- The reviewed path set is fixed per loop (as before); a loop whose scope changes needs a new attempt.
- Rename pairs are covered only through the path list (both old and new names are in `changed_paths`).
