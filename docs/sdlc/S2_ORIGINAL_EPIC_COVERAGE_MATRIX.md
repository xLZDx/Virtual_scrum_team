## How to read this reconciliation

The original S2 plan defines eight epics, E1–E8, and two deferred S2 items, D1–D2. The later `S2-1` through `S2-5` stories consolidate requirements and add transport, bundle, provenance, and gate work; they do **not** replace or reduce the E1–E8 and D1–D2 acceptance denominator. A pass for a later story is not automatically evidence for an original epic.

The original plan defines semantic denominators (the complete listed cases for each epic), not one stable pytest-ID count. The historical inventory of 209 collected IDs, 189 passed across Windows/WSL, and 20 `NOT_RUN` belongs only to the six modules and source/test HEAD recorded in `s2-safe-functional-exact-4c1692d-20261027.md`. It is not the current denominator: modules and acceptance scope grew afterward. Later runs use different overlapping components and revisions, so their counts must not be added into a project-wide total. S4's 53 policy selectors are not S2 selectors and are excluded from this matrix.

`PASS` below means only the named test behavior passed at the cited source/test revision. It does not imply current-head acceptance, a provisioned system, real authorization, or production-runtime evidence. `NOT_RUN` is not a failure and cannot be promoted to pass; skipped tests remain unverified.
